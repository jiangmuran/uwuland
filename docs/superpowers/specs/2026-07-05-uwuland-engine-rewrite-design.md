# UWULAND 引擎重构设计文档

- 日期：2026-07-05
- 状态：待用户review

## 背景与目标

UWULAND 现在是一个零构建、纯 vanilla JS/CSS/HTML 的文字游戏：`game-engine.js` 逐行解析 `drama-init.js` 里内嵌的自定义指令文本（`!pause/!pick/!head/!load/!exit/!clear/!wait`），`ee-main.js` 负责窗口拖拽/设置/存档等 UI 逻辑，`style.css` 是一套像素级绝对定位的仿桌面窗口复古 UI。

现状的三个主要问题：

1. **完全不支持手机**：`style.css` 里宽度<792px或高度<544px时会直接隐藏游戏、显示"你的屏幕太小了"报错，是硬拦截而非体验差。
2. **引擎太朴素**：纯线性文本 + `!pick` 跳转，没有变量、数值、物品、条件判断，选择的唯一后果是"跳到哪一段文本"，本质是视觉小说而非游戏。
3. **解析器写法比较hacky**（`.split(' ')`拼字符串），复杂度一旦上升容易变得难以维护。

本次是"完全重构"：抛弃 `game-engine.js`，用 TypeScript + Vite 重写一个新引擎，在保留原有 UI 视觉风格（配色/字体/圆角/动画/仿窗口造型）的前提下适配手机端，并让现有 4 章剧情真正用上变量、好感度、物品、互动谜题这些机制，而不只是留空接口。

## 目标（Goals）

- 新引擎：TS 编写的词法分析器 + 递归下降解析器，支持变量/数值、布尔 flag、物品(inventory)、条件分支(`!if/!elif/!else/!endif`)、带条件门槛的选择、可插拔的互动谜题/小游戏。
- UI 视觉风格与现在保持一致（配色 `#7D5A30`/`#eDcAa0`、字体栈 Consolas/Yahei/Yu Gothic、圆角、shake/blink-caret/bit-shake/title 等动画、仿桌面窗口造型），但底层用响应式布局重写，不再是硬编码像素坐标。
- 手机端从"报错拦截"改为原生全屏一等公民布局，视觉语言与桌面端保持一致可辨认。
- 现有 4 章剧情主线保留，按章节分配新机制（flag、好感度、背包、互动谜题、多结局），实际提升可玩性，不是纯对话/看剧情。
- 存档系统支持新的状态模型（变量/flag/物品），本地 2 档（auto/manual）沿用现在的槽位设计。
- 保留 Apache-2.0 协议要求的署名以及 README 里对 PAPEREE 的署名要求。

## 非目标（Non-goals）

- 不做云存档/账号系统，仍然是纯前端 localStorage、无后端。
- 不保证旧版(v1.30及以前)存档兼容，完整重写允许存档格式作废。
- 不在本轮把 4 章剧情做成"每章都有完整多结局"的重度分支，只做本文"内容强化与分期"里列出的具体点；更大规模的内容扩写留到后续版本。
- 不引入 React/Vue 等重量级前端框架，渲染层保持轻量自定义实现。

## 架构总览

```
src/
  engine/    — 纯逻辑层，不碰 DOM：lexer → parser → interpreter，GameState，表达式求值器，存档序列化
  content/   — 每章一个纯文本 .script 文件（从 drama-init.js 里的大对象拆出来）
  ui/        — 渲染层：订阅 engine 状态变化更新 DOM；桌面/手机两套响应式布局共享同一份视觉 token
  audio/     — 音效播放
  main.ts    — 启动装配（加载存档 → 初始化 GameState → 挂载 UI → 启动解析）
```

`engine/` 不依赖任何浏览器 API，可以脱离 DOM 单独单元测试；`ui/` 是唯一操作 DOM 的地方。这是相对现在"解析、状态、DOM操作糅在一个文件里"的最大结构性改变。

数据流：`content/*.script`（文本）→ `engine/parser` 产出 AST → `engine/interpreter` 逐节点执行，读写 `GameState`，通过事件/回调把"要渲染的东西"（文本行、选项、谜题、头像变化）交给 `ui/renderer` → renderer 更新 DOM 并等待用户交互（点击/选择/谜题结果）→ resolve 后交还 interpreter 继续往下走。

## DSL v2 设计

延续现有纯文本 + `!command` 的写法和 `*`(小)/`^`(大)/`&`(斜体) 文本标记，保留 `!pause/!load/!exit/!pick/!head/!clear/!wait`，新增：

| 指令 | 作用 |
|---|---|
| `!set var=expr` | 通用赋值，右侧是完整表达式（可引用其它变量），用于稍复杂的计算 |
| `!stat name +N` / `-N` / `=N` | 数值变量最常见用法（好感度等）的简写，等价于 `!set name=name+N` 等 |
| `!flag name` / `!unflag name` | 设置/清除布尔 flag |
| `!item add name` / `!item remove name` | 背包增删 |
| `!if expr` ... `!elif expr` ... `!else` ... `!endif` | 块级条件，包裹任意文本行或指令行 |
| `!pick 选项1\|选项2 目标1\|目标2 :: 条件1\|条件2` | 在现有 `!pick` 基础上加可选的 `::` 门槛，条件不满足的选项不显示；省略 `::` 时全部可选，**完全向后兼容现有 `!pick` 写法** |
| `!puzzle 谜题名` | 调用注册好的互动谜题组件，阻塞脚本直到玩家完成，结果自动写回变量/flag |

表达式语法（用于 `!if`/`!elif`/`!pick ::`）：

- 比较：`>= <= == != > <`
- 布尔组合：`&&` `||` `!`，支持括号分组
- 变量/flag 引用：裸名（如 `affinity_bird`、`met_foolishbird`），flag 未设置时视为 0/false
- 背包检查：`has 物品名`

优先级从高到低：`!`（取反）> 比较运算符 > `&&` > `||`。

会实现真正的词法分析器 + 递归下降解析器（替代现在 `.split(' ')` 的拼字符串写法），配合单元测试覆盖条件嵌套、`!pick ::` 门槛、变量/物品变更等场景，避免复杂度上升后又变得难以维护。

## 状态与存档

`GameState` 结构：

- `position`：当前章节 + 行号（对应现在的 `TAG`，用于续读）
- `vars`：`Record<string, number>`，数值变量（好感度等）
- `flags`：`Set<string>`，布尔 flag
- `inventory`：`Set<string>`，持有物品
- `head`：当前头像颜色/图片（cosmetic 状态，行为与现在一致）

存档序列化在现有 `{TITLE, TAG, HEAD, TIME}` 基础上加上 `vars`/`flags`/`inventory` 的 JSON 序列化，继续存 2 档（`auto`/`manual`），存读档 UI（Data/Pace/Time 展示）沿用现有交互。

**假设/待确认**：旧版 (v1.30 及更早) 存档在新引擎下直接作废，不做迁移——加载时如果发现存档格式对不上新 schema，按"无存档"处理，不会崩溃。

## 渲染与移动端适配

把现在硬编码像素坐标的 CSS（如 `left:208px;top:240px`）重构为基于 flex/grid + CSS 自定义属性的响应式布局。颜色（`#7D5A30` 描边 / `#eDcAa0` 点缀）、字体栈（Consolas/Microsoft Yahei/Yu Gothic）、圆角、动画（shake/blink-caret/bit-shake/title渐隐）保持不变，作为共享视觉 token 被桌面端和移动端两套布局复用。

- **桌面端**：保留可拖拽的仿桌面窗口造型（标题栏、⊖/⊗、底部任务栏、右下角 state 面板），布局观感与现在基本一致。
- **移动端**：改为原生全屏布局——标题栏简化为顶部条，头像 + 对话内容纵向铺满宽度，选项按钮全宽（触控友好），底部工具栏（Home/Save/Load/Set/About）常驻。彻底移除现有 `#small-screen`"屏幕太小"报错拦截逻辑，手机是一等公民而非报错分支。
- 好感度/数值展示：移动端做成常驻小图标条，点击展开背包抽屉；视觉上复用现有存档卡片（`.box`）的描边、圆角、hover 风格保持一致性。

## 谜题/小游戏框架

定义一个轻量的 Puzzle 接口：谜题组件挂载到指定容器，玩家完成后通过回调把结果（成功/失败/自定义变量）交回引擎；引擎的处理方式与现在 `!pause` 等待点击一致——await 谜题结果后再继续往下解析脚本。

第一个具体谜题直接复用现有素材：第三章"Base64解密"目前是直接把答案放在 `!pick` 选项里，改造后变成真正的输入框谜题（玩家自己解码后输入答案，答错可重试，多次错误后给出提示）。后续新增谜题以插件形式接入，不需要改动引擎核心。

## 内容强化与分期

4 章剧情主线保持不变，按章节分配新机制落地点（具体新增台词在实现阶段会拿给用户一起看/改，不会单方面替用户写死剧情走向）：

- **一、白色的鸟**：引入 flag 体系 + 第一批好感度选择点
- **二、灰色的屋**：引入背包机制
- **三、绿色的门**：Base64 解密改造成互动谜题 + 一个物品门槛的关键选择
- **四、蓝色的海**：根据累计好感度/flag/物品分出至少 2 种结局文本，替代现在单一的"未完待续"

## 测试策略

- `engine/` 核心（lexer/parser/表达式求值/interpreter）用 Vitest 写单元测试，覆盖条件嵌套、`!pick ::` 门槛、变量/物品变更、存档序列化往返等场景。
- UI/动画/响应式断点/音频这类难以自动化断言的部分，实现完成后会实际启动 dev server，在桌面尺寸和手机尺寸视口下手动过一遍再确认完成，不仅凭类型检查/单测就宣称完工。

## 署名与协议

沿用 Apache-2.0 协议要求的署名，以及 README 中"保留原作者 PAPEREE 信息"的要求，新版关于页/state 面板会延续对应的署名信息（具体文案在实现阶段定稿）。
